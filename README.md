# 四国军棋记牌器（iOS · 2V2 暗棋）

微信小程序四国军棋 2V2 暗棋的实时记牌 + 推演工具。纯本地方案，只读取屏幕上**公开可见**的信息
（棋子有无、战斗结果、我方/队友明子），不读取游戏任何隐藏数据。

## 功能对照

| 需求 | 实现 |
|---|---|
| 记录敌方（左右家）实时剩余棋子 | 录屏帧 → 129 节点占用/配色识别 → 每家 25 枚实时计数、阵亡构成、存活构成期望 |
| 推演"吃我/队友棋子的敌方棋子大小" | 约束传播引擎：吃掉已知身份的子 ⇒ 该子 ≥X；挖雷 ⇒ 工兵；同归于尽 ⇒ 炸弹；移动过 ⇒ 非地雷/军旗；叠加"剩余构成容量"全局剪枝，输出每个敌子的候选身份与概率 |
| 棋谱 OCR 导入（可增删） | 相册多选截图 → Vision 中文 OCR → 自动解析棋子统计/布阵条目 → 可编辑、删除；「布阵棋谱」可一键套用为本局我方/队友身份 |
| 相机功能 | ① 系统录屏采集（ReplayKit 广播扩展，推荐）② 相机取景（拍摄另一块屏幕） |
| 悬浮球边看边下 | iOS 不允许第三方悬浮窗压在微信上，采用**自定义画中画**（AVSampleBufferDisplayLayer PiP）：实时数据渲染成视频帧，以画中画小窗浮在游戏上方；App 内另有可拖动悬浮球 |

## 架构

```
ReplayKit 广播扩展(BroadcastExtension)
   └─ 屏幕帧 → 缩放/JPEG → App Group 共享文件 + seq
主 App(GameSession 轮询)
   ├─ VisionPipeline: 129 节点占用(对比度/边缘) + 归属(色相) + 连续2帧稳定化
   ├─ 事件配对: 移动 / 吃子(占位变色) / 同归于尽(双清空) / 阵亡(孤立清空)
   ├─ InferenceEngine: 敌方棋子实例 + 候选身份约束传播 + 构成容量剪枝
   ├─ OCR: 我方/队友明子节点 OCR（身份 → 推演约束）
   └─ UI: 仪表盘 / 示意棋盘(点按修正) / 棋谱库 / 设置
        └─ PiPManager: 数据卡 → CVPixelBuffer → 画中画悬浮窗
```

推演规则（引擎内置）：
- 敌子吃掉我/队友已知 X ⇒ 该子 ∈ {rank > X}（排除炸弹，炸弹会同归）
- 我/队友已知 X 吃掉敌子 ⇒ 该阵亡敌子 < X
- 敌子与我已知 X 同归于尽 ⇒ 该敌子 = 炸弹（X 非炸弹时）
- 敌子挖掉我方地雷后存活 ⇒ 工兵；撞雷阵亡 ⇒ 非工兵非炸弹
- 任何移动过 ⇒ 排除地雷/军旗；进入大本营后不能再动
- 全局剪枝：每个等级的"存活+阵亡"不超过初始数量（司令1 军长1 师长2 旅长2 团长2 营长2 连长3 排长3 工兵3 地雷3 炸弹2 军旗1 = 25）

## 无需 Mac 的安装路径（GitHub Actions 云构建 + 爱思助手自签）

项目内置 `.github/workflows/build.yml`，在 GitHub 免费云服务器上完成编译，产出两个未签名 IPA：

1. 注册 GitHub 账号 → 新建仓库（Public 免费）→ 用网页端把 `SQJQTracker` 整个文件夹拖拽上传（含隐藏的 `.github` 目录）。
2. 仓库页 → **Actions** 标签 → 若提示启用则点启用 → 选择 "Build IPAs" → **Run workflow**。约 5~10 分钟。
3. 运行完成后在该次运行页底部 **Artifacts** 下载：
   - `SQJQTracker-Lite-unsigned-ipa`：精简版，免费 Apple ID 自签可装（无录屏采集，可测 UI/棋谱 OCR/校准诊断/相机）。
   - `SQJQTracker-Full-unsigned-ipa`：完整版，需付费开发者证书或企业签（见下）。
4. 爱思助手（Windows）签名安装：数据线连接手机 → 工具箱 → **IPA 签名** → 选择下载的 IPA →
   - 免费自签：用 Apple ID 登录直接签（有效期 7 天，每 7 天重签一次，免费 ID 最多 3 个应用）；
   - 付费证书：开发者后台生成 p12 + mobileprovision，用"使用证书签名"；
   - 企业签：把完整版 IPA 交给签服务处理。
5. 安装后首次启动：设置 → 通用 → VPN与设备管理 → 信任对应开发者证书。

> 说明：精简版没有 App Group 权限，录屏广播采集不可用（单手机场景下也没有其他抓屏途径）；相机取景只对"另一块屏幕"有意义。完整功能（实时记牌+推演）需要付费开发者账号签名。

## 构建步骤（需要一台 Mac + Xcode 15+）

1. 安装 [XcodeGen](https://github.com/yonaskolb/XcodeGen)：
   ```bash
   brew install xcodegen
   ```
2. 生成工程：
   ```bash
   cd SQJQTracker
   xcodegen generate
   open SQJQTracker.xcodeproj
   ```
3. 签名（**必须付费开发者账号**：广播扩展 + App Group 不支持免费签名）：
   - Xcode → 两个 target（SQJQTracker、BroadcastExtension）→ Signing & Capabilities → 选择你的 Team
   - 确认两个 target 的 App Groups 都勾选了 `group.com.sqjq.tracker`（首次会提示注册，点确认）
4. iPhone 连接 Mac，运行主 target（真机；模拟器不支持录屏广播与画中画）。

## 使用流程

1. **校准**（首次必做，之后记住）：设置 → 棋盘校准 → 抓取最新画面（或相册截图）→ 把 4 个黄点拖到棋盘外框四角 → 打开网格确认 129 个点都落在交叉位上 → 需要时微调"占用灵敏度阈值" → 运行诊断（四家应各 25 有子/5 行营为空）→ 保存。
2. **录屏采集**：设置 → 录屏采集 → 选择"记牌器采集"开始录制。
3. **开始本局**：回到 App 仪表盘点"开始本局"，然后切到游戏布阵界面——App 自动抓基准帧并学习四家配色。
4. **对局中**：切回微信下棋。想边看边下：App 里点"启动"（设置→画中画悬浮窗），再切到微信，小窗浮在游戏上方实时刷新；App 内悬浮球随时可看两家剩余。
5. **推演**：敌方吃掉你/队友棋子时，"敌方推演结果"给出该子候选与概率；点棋盘任意节点看详情；识别错了可手动修正、撤销。
6. **棋谱**：棋谱页导入截图（复盘/战绩图）OCR 保存；布阵棋谱格式：每行 `我 3-2 军长`（行1~6=前排→后排，列1~5=该玩家左手→右手，队友写 `友`），可在开局前套用，让推演从第一手就精确。

## 调参与排障

- 识别不稳：校准页调阈值；确保微信对局时棋盘完整无遮挡、亮度稳定。
- 没有事件产生：确认红色录制条在走、`开始本局` 已点、棋盘四角校准贴合。
- PiP 黑屏：等待第一帧数据；PiP 仅真机可用；重启 App 重试。
- 帧率/清晰度：设置页采样间隔、JPEG 质量、分辨率上限（扩展每 5 秒热读取，即时生效）。
- 后台保活：PiP 启动后 App 会持续运行（内置静音播放保活）；未开 PiP 时 App 切后台约 30 秒后暂停跟踪，回前台自动恢复。
- 日志：Xcode Console 过滤 `sqjq`；或"设置→导出事件日志"。

## 已知限制

- 微信小程序棋子配色若左右敌家相同，中央节点的归属判定会退化为按阵地推断（README 建议在校准页用"诊断"确认配色可分）。
- 战斗动画瞬间可能产生偶发误事件，用"撤销"或点节点修正即可，计数始终按节点状态兜底。
- v1 推演为规则+容量估算，不做深度搜索；棋谱数据当前用于身份预载与统计参考。

## 合规声明

工具只做"公开信息自动笔记"，不破解、不注入、不读取隐藏数据。但**实时辅助可能违反游戏平台用户协议**，请仅用于个人学习研究，风险自担。
